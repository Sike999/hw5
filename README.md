1) Чем useCallback отличается от useMemo? Когда использовать каждый?
2) Почему React.memo не помогает, если колбэк передаётся без useCallback?
3) Когда стоит использовать useReducer вместо useState? По какому признаку вы принимаете это решение?
4) Что такое useRef и почему изменение .current не вызывает ре-рендер?
5) Зачем useContext нужен провайдер (Provider)? Что произойдёт, если использовать useContext вне провайдера?
6) В чём разница между controlled и uncontrolled инпутом? Как React Hook Form использует uncontrolled подход?
7) Почему zodResolver — это не валидация на сервере? Где ещё нужно валидировать данные?

1) useCallback отличается от useMemo тем, что в callback обычно возвращает саму функцию вычисления,а в useMemo результат вычисления. Используются когда нужно сохранить либо функцию либо данные соответсвенно.
2) Потмоу что в таком случае ссылка на колбек становится нестабильной, создается каждый ререндер, и мемо компонент видит что пропс(колбек) поменялся и рендерится.
3) useReducer нужно использовать когда нужна какая то сложная обработка изменения состояния
4) useRef это хук который позволяет выйти из циклов Vdom React. .current хранит данные внутри реального дерева, поэтому его изменения проходят мимо reconsiliation
5) Провайдер нужен чтобы компоненты внутри него подписались на изменение данных из контекста. Если вызвать useContext вне провайдера то не получится получить никакие данные
6) когда в том же компоненте где находятся инпуты определяют стейт для каждого, это controlled инпуты, то есть инпутом управляет React. uncontrolled инпуты это когда инпутами управляет DOM. React Hook Form реализовал uncontrolled подход за счет использования useRef под капотом
7) zodResolver это специальный объект для React Hook Form чтобы подтянуть схему валидации на объект RHF. Валидируют еще на сервере перед отправкой на фронт, на фронте перед CRUD действиями, на фронте после получения данных с сервера
